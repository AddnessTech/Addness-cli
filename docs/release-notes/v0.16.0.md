# v0.16.0

CLIの過剰な連続呼び出しを抑え、MCP経由の通信をREST専用コマンドへ移しました。

- `addness mcp` とMCPクライアントの通信実装を撤去しました。
- `goal detail`、ページ指定付きの `member objectives`、`crm list/get/rows`、`chat attachment` をRESTで提供します。本文・設定・行など、必要な範囲だけ取得できます。
- 同じ接続先・APIキーのREST送信に、直近60秒60回・直近3600秒600回の上限を設けました。複数プロセスで共有し、成功する読み取りループも送信前に停止します。接続失敗や読み取りの再試行も回数に含みます。
- TUIのエージェント実行中の自動更新を3秒から60秒間隔に変更し、待機中の定期取得を減らしました。
- 429の待機期限も共有し、`Retry-After` を尊重します。最低60秒から、繰り返す場合は最大1時間まで待機を延ばします。サーバー指定がさらに長い場合はそちらを優先し、429を自動再送しません。
- 添付ダウンロードは既存ファイルを上書きせず、配布先へAPIキーを送らず、最大64MiBに制限します。
- `pulldown-cmark` をセキュリティ修正版0.13.6へ更新しました。

破壊的変更: `mcp list/schema/call/info` は使用できません。`member objectives` は既定で未完了・最大100件・子目標数なしになります。Analytics/KPI・CRM書き込み等、MCPだけで利用できた機能の一部は専用CLI未対応です。[移行手順と対応範囲](https://github.com/AddnessTech/Addness-cli/blob/v0.16.0/docs/rest-cli-migration.md)を確認してください。

上限に達したら、表示された待機時間を守り、取得済みの結果を再利用してください。複数のAPIを使う操作が途中停止した場合は、結果を確認して未処理分から再開してください。この対策には自動処理で使用しているCLIの更新が必要です。旧版や別端末の処理を強制停止するものではありません。
